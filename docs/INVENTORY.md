# Function inventory

Every function in the retail `HydroThunder.exe` (UWP build), with what this repository does about it.
Generated by `hydro-tools/census/inventory.py` (kept outside this repository) from measured inputs - regenerate rather than edit.

## How the status is decided

| status | meaning |
|---|---|
| **verified** | retail's own code was **executed** in an oracle case (`hydro-tools/oracle`) **and** this repo's source cites the address - a recreation checked against retail's output by `--selftest`. |
| **callee** | retail executed it inside a checked case, but the source never cites it: a CRT / STL / engine helper reached through a verified function, not recreated on its own. |
| **cited** | the source cites the address but no oracle case runs it - recreated or referenced, **not** checked. |
| **absent** | neither: not recreated. |

Subsystems come from the RTTI class whose vtable holds the function (1253 classes, 1564 vtables). Functions in no vtable take the subsystem of the nearest class method before them when it is within 0x800 bytes (MSVC emits a translation unit contiguously); those rows say `(by address)` in the CSV - a placement guess, not a reading. The rest are `unattributed`.

## Where to look

`inventory.csv` has one row per function: address, size, IDA name, owning classes and vtable slots, subsystem, status and the source files that cite it. Filter it by `status` and `subsystem` to pick the next work.
